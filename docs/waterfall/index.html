Waterfall SDLC

The sequential SDLC model where each stage completes and signs off before the next stage starts.

How Waterfall works

In Waterfall, work flows downward through requirements, system design, implementation, testing, deployment, and maintenance. Each stage ends with a formal review gate and frozen documentation. Moving backward to change an earlier decision requires a formal change request.

Where Waterfall works well

  • Fixed-price vendor contracts where scope, deliverables, and payment milestones must be agreed before work begins.
  • Hardware-coupled or embedded systems where physical manufacturing deadlines lock interfaces early.
  • Small, well-understood internal migrations where requirements are already documented and stable.
  • Audited regulatory environments that require signed stage-gate evidence before code enters production.

Where Waterfall breaks down

Because integration and testing happen near the end of the schedule, misunderstood requirements or architectural bottlenecks stay hidden for months. When schedules slip during implementation, testing is often compressed to keep the launch date, which raises production defect rates.

Modern hybrid: Water-Scrum-Fall

Many enterprises combine Waterfall budgeting and annual release governance with Agile engineering sprints inside the build phase. This keeps financial predictability while still letting developers test and integrate code continuously.
