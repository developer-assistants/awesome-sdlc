Waterfall SDLC

The sequential SDLC model where each stage completes, passes a formal gate review, and freezes its specification before the next stage starts.

Stage gates and deliverables

In Waterfall, progress moves downward across distinct phases. Each gate requires documented sign-off so scope, cost, and schedule stay locked:

StagePrimary deliverableSign-off authority
1. Feasibility & PlanningProject charter, budget, master Gantt scheduleExecutive sponsor
2. RequirementsBaselined Software Requirements Specification (SRS)Business owner & compliance
3. System DesignHigh-level (HLD) and low-level (LLD) design specsArchitecture Review Board
4. ImplementationCompiled build, unit tests, code inspection logsEngineering lead
5. Verification & UATTest execution report, defect closure log, UAT sign-offQA lead & client
6. Release & MaintenanceProduction cutover, operations manual, support SLAOperations / Change board

How scope changes work: the Change Control Board (CCB)

Once the SRS is baselined, developers do not accept informal scope additions. Any requested change goes through a Change Control Board (CCB) that evaluates schedule impact, budget delta, and test-plan updates before approving or deferring the request. This prevents silent scope creep on fixed-price contracts.

Where Waterfall works well

  • Fixed-price vendor contracts where scope, acceptance tests, and payment milestones must be legally defined before work starts.
  • Hardware-coupled or embedded systems where physical manufacturing deadlines lock electrical and protocol interfaces months ahead.
  • Well-understood regulatory reporting or data migrations where rules are published by an external authority and rarely change mid-year.
  • Multi-vendor enterprise integrations requiring formal interface control documents (ICDs) between separate companies.

Where Waterfall breaks down

Integration and system testing happen near the end of the timeline, so hidden assumptions in the SRS or performance bottlenecks often surface months after coding began. When implementation slips, teams frequently compress testing to hold the launch date, shipping high defect counts into production.

Modern hybrid: Water-Scrum-Fall

Many large enterprises run Waterfall budgeting and compliance sign-offs at the portfolio level while engineering teams execute two-week Agile sprints with automated CI/CD inside the build phase. This preserves executive predictability while catching integration defects early.
