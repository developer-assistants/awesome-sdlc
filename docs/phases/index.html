The 7 phases of the software development life cycle

Every phase takes a concrete input, produces a verifiable artifact, and reduces a specific class of delivery risk.

PhaseGoalTypical artifactsExit gate
1. PlanningConfirm feasibility, scope, budget, and schedule.Project charter, risk registerStakeholder go/no-go approval
2. RequirementsTurn goals into testable functional and non-functional specs.PRD, SRS, user storiesSigned-off acceptance criteria
3. System designDefine architecture, database schema, APIs, and security.Architecture doc, ERD, OpenAPI specDesign review sign-off
4. ImplementationWrite clean, reviewed code and automated unit tests.Commits, pull requests, CI buildsMerged PRs with green CI
5. TestingVerify correctness, performance, and security before release.Test plan, QA report, load testZero open Sev-1/Sev-2 bugs
6. DeploymentShip to production with minimal downtime and rollback safety.Release notes, runbook, telemetryProduction health checks pass
7. MaintenanceMonitor, patch, and evolve the live system.Post-mortems, patches, backlogContinuous SLO compliance

1. Planning

The team agrees on why the project exists, who pays for it, and what is out of scope. Example: before building a self-serve billing portal, the engineering manager estimates six weeks for two backend engineers and one frontend engineer, confirms Stripe fees, and explicitly defers multi-currency invoicing to phase two.

2. Requirements analysis

Product and engineering translate business goals into concrete specifications. Functional requirements describe what the system must do (for example, "users can download PDF invoices for the past 24 months"). Non-functional requirements define constraints such as p95 latency under 250ms, 99.9% uptime, and PCI compliance boundaries.

3. System design

Engineers choose data stores, service boundaries, authentication flows, and failure handling. Writing a short Architecture Design Document (ADD) before coding surfaces expensive mistakes such as missing database indexes, unversioned API payloads, or single points of failure. Grab a starter in our Template Builder.

4. Implementation

Developers write code against small, reviewable pull requests. Modern teams pair implementation with continuous integration: every push runs linters, type checks, static security scans, and unit tests automatically.

5. Testing

QA and developers verify the build across multiple layers: unit tests for logic, integration tests for database and API contracts, end-to-end tests for critical user flows, and load tests for peak traffic. In regulated industries, users also complete formal User Acceptance Testing (UAT) in staging.

6. Deployment

Code moves to production through automated pipelines. Teams reduce blast radius using blue-green deployments, canary rollouts (sending 5% of traffic to the new version first), and backward-compatible database migrations so rollbacks stay safe.

7. Maintenance

Most software spends 70% or more of its life in maintenance. Maintenance falls into four categories: corrective (fixing bugs), adaptive (updating for new OS or API versions), perfective (improving speed or usability), and preventive (refactoring and dependency upgrades).
