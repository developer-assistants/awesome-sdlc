Core SDLC fundamentals

1. What are the seven phases of SDLC in order?

Planning, requirements analysis, system design, implementation, testing, deployment, and maintenance. Some organizations merge planning and requirements into a six-phase model.

2. What is the difference between verification and validation?

Verification checks whether the software matches its specification ("did we build the product right?") via reviews, static analysis, and unit/integration tests. Validation checks whether the software solves the user problem ("did we build the right product?") through UAT and customer feedback.

3. Why is fixing a bug in production so much more expensive than in design?

In design, a fix is a quick edit to a spec or diagram. In production, it triggers incident response, debugging live traffic, writing a backward-compatible patch, migrating corrupted data, running regression tests, and communicating with affected users.

4. What is the difference between functional and non-functional requirements?

Functional requirements define what the system does (features, workflows, calculations). Non-functional requirements define how well it operates (latency, throughput, uptime SLO, encryption, accessibility, and regulatory compliance).

Models: Agile, Waterfall, V-Model, Spiral

5. When would you choose Waterfall over Agile?

Choose Waterfall when requirements are fixed and verified up front, external compliance requires signed stage gates, or the project is a fixed-scope vendor contract where mid-project scope changes are disallowed.

6. How do Scrum and Kanban differ inside Agile SDLC?

Scrum uses fixed-length sprints with planned commitments, demos, and retrospectives. Kanban uses continuous flow with explicit work-in-progress (WIP) limits and no mandatory sprint boundaries.

7. What is the main weakness of the V-Model?

Like Waterfall, the V-Model assumes requirements stay stable. If product needs change halfway through implementation, both specification documents and paired test plans have to be rewritten.

8. When does the Spiral model make sense?

Use Spiral for large, high-risk, or novel engineering efforts where retiring a technical unknown via early prototypes matters more than minimizing upfront risk-analysis overhead.

Testing, CI/CD, and Security (DevSecOps)

9. What is shift-left testing?

Shift-left testing moves quality checks earlier in the lifecycle: reviewing requirements for testability, writing automated unit and contract tests during development, and running security scanners on every pull request rather than waiting for a final QA stage.

10. What is a Requirements Traceability Matrix (RTM)?

An RTM links every requirement ID to its design component, test cases, and release verification result. It proves that every requirement was tested and helps auditors verify compliance.

11. How do CI/CD pipelines fit into SDLC?

Continuous Integration automates building, linting, and testing every commit. Continuous Delivery and Deployment automate artifact packaging, staging verification, and canary or blue-green production rollouts.

12. What is the difference between SAST and DAST in Secure SDLC?

SAST (Static Application Security Testing) scans source code and dependencies during implementation without running the app. DAST (Dynamic Application Security Testing) probes a running staging instance from the outside to catch runtime auth, header, or injection flaws.

Architecture, Deployment, and Maintenance

13. How do you run zero-downtime database migrations?

Use expand-and-contract migrations: add new nullable columns first, deploy code that writes to both old and new fields, backfill existing rows, switch reads to the new column, and drop the old column in a later deployment.

14. What is the difference between blue-green and canary deployments?

Blue-green runs two identical production environments and flips 100% of traffic from old (blue) to new (green) at once. Canary routes a small slice of live traffic (such as 5%) to the new version first and expands gradually only if error rates and latency stay healthy.

15. What are the four types of software maintenance?

Corrective (bug fixes), adaptive (environment, OS, or dependency updates), perfective (performance and UX improvements), and preventive (refactoring and technical debt reduction).

16. What makes a post-mortem effective after a production outage?

A useful post-mortem is blameless, documents an exact UTC timeline, identifies systemic root causes (missing alert, unsafe migration, untested failover), and assigns dated engineering action items tracked to completion.
